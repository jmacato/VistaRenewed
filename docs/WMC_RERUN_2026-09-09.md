## Follow-up: queued-flip experiment and address correction

Package 33 advertised a single queued flip without implementing vblank-latched
retirement. It stalled the interactive desktop while the SYSTEM control service
remained responsive. Package 34 corrected zero-offset framebuffer address
publication but retained those caps and reproduced the stall. Neither is a
validated performance fix. Logs are `audit33-stalled-kmd.log` and the current
package 34 capture. Live PnP updates timed out; signed SYS replacement was
verified byte-for-byte before the cold boot.

The address correction distinguishes a valid DMA address (including zero) from
a blt/creation promotion with no new scheduler address. The production-code
harness covers zero and nonzero addresses, blt preservation, stale generations,
incompatible resources and allocation references. Reintroducing the original
zero-address condition makes the test fail. x64 and x86 package 34 builds passed.

Package 35 removes the queued-flip capability experiment, keeps the address
correction, and adds bounded requested-interval/address diagnostics. Runtime
validation is pending; synchronized presentation remains unresolved.

Package 35 cold-booted to a responsive Aero desktop (Run dialog and sidebar
updates observed). Native D3D9Ex fullscreen RGB readbacks passed, but interval
one measured 173.09 FPS at 60 Hz and 177.63 FPS at 300 Hz. The driver trace
confirmed DWM requests interval=1 with flags=4, alternating addresses
0xc0000000/0xc0384000 with vblank interrupts enabled. Thus correct interval
requests reach the kernel, where retirement currently ignores them.

Package 36 is an unvalidated ordering experiment: reserve the next requested
vblank(s), suppress timer CRTC notifications while this synchronized DMA flip
is outstanding, complete the copy and DMA notification, then emit the deferred
CRTC notification. This differs from package 30's wait-only experiment, which
continued publishing CRTC notifications during the outstanding flip. Local
harnesses cover interval counts, sequence wrap, timeout/stop cancellation and
timer notification suppression. Both architecture builds passed; runtime
validation is still required. Package 35 source and signed media are retained
as the responsive fallback.

Review found a concrete defect in the earlier package 30 wait experiment:
`RecordFailure(WaitForVblank(...))` passed success to a function that deliberately
converts NT_SUCCESS results to STATUS_UNSUCCESSFUL. Package 36 repeated this
mistake; package 37 guards RecordFailure with !NT_SUCCESS. The new production
command-path regression test verifies successful waits do not become DMA
faults, immediate presents bypass waiting, and real failures propagate. Its
negative control reintroduces the unconditional call and fails as expected.
This is a plausible explanation for the package 30 scheduler fault; the earlier
attribution to waiting alone was not established. Package 37 still requires
normal-mode runtime validation.

## Verified package 37 results and additional windowed defect

The synchronized-present correction passes all six fullscreen variants (native
and WOW D3D9/Ex plus Ex video): 59.75–60.69 FPS at 60 Hz. Four immediate variants
remain unrestricted at 138.40–190.53 FPS across the tested modes. Every variant
passes its RGB readbacks and valid active/blank raster checks. The revised probe
also rejects a 60 Hz synchronized result below 50 FPS, avoiding a false pass for
half-rate presentation.

WinSAT ALU: Valid=1, FPS=96.49, EffectiveFPS=89.55. Fullscreen texture: Valid=1,
FPS=205.02, EffectiveFPS=197.34. Twelve independent QMP screenshots during the
fullscreen RGB test and cursor movements contained exactly 921600 pixels of the
expected red, green or blue. These captures validate framebuffer integrity;
QMP screendumps do not independently establish hardware cursor visibility.
Native and WOW shared-texture create/open/readback tests checked 65536 pixels
with no mismatches (same process/device; cross-process coverage is separate).

The final package 37 WMC navigation recording combines keypresses and screenshots
in one loop. Ten reviewed screenshots show five distinct selected menu rows.
3129 host scanout completions span 23.998 seconds; median interval 6.926 ms,
p95 10.195 ms, maximum 34.963 ms. These are host completion intervals, not
physical monitor FPS or a count of unique animation frames. Earlier attempts
with separate shell processes captured screenshots after navigation ended;
those images cannot be used as navigation evidence. Both DWM and ehshell loaded
neptune_d3d9.dll.

Additional normal-user legacy D3D9 windowed probes failed on package 37 in both
architectures, for both screen-sized popups and ordinary 640x480 windows.
The UMD trace identifies Blt failing with D3DERR_NOTAVAILABLE. Verbose tracing
records Flags=0x500: BeginPresentToDwm|EndPresentToDwm. The old mask allowed only
Point and Linear, rejecting normal Vista compositor presentation markers.
Package 38 accepts these marker bits while preserving rejection of unsupported
colour-key, mirror, rotation and sRGB operations. The production helper test and
its negative control cover this defect. Both UMD architecture builds and Vista
PE/ABI audits pass. Package 38 runtime validation is in progress.
